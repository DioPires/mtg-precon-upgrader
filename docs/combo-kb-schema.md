# Combo Lab Knowledge-Base Schema (DEC-476 Phase 1 / DEC-488)

The per-card semantic layer the Combo Lab's Tier-C synergy engine (Phase 2) and
Tier-B verifier (Phase 3) consume. This document is the contract those phases
build on: storage layout, field semantics, provenance encoding, and version
stamps. It implements PRD §7.2 (KB-1..KB-7), DR-1/DR-2, and the enforced Tier-B
provenance gate (build-plan decision 6b).

## 1. Storage layout

```
data/combo-kb/
  ontology.json            # versioned feature/resource/event/guard ontology (source of truth)
  meta.json                # build meta: versions, counts, provenance + feature histograms
  entries/{shard}.json     # KB entries, sharded by oracle_id[:2] (256 shards)
  ontology-gaps.json       # QE-3 gap log (written by the classifier when a mechanic is unmodelled)
```

- Committed artifacts are **plain JSON, `sort_keys=True`, `indent=2`**, one
  trailing newline — stable key order so git packs delta-compress the weekly/
  per-set diff (Phase-0 precedent). Full-pool KB is ~41 MB across 256 shards,
  well under the ~150 MB working-tree gate.
- Sharding by `oracle_id[:2]` keeps each shard ~120 cards at full coverage and
  lets later phases fetch only the shards they need (same lever as the Spellbook
  details tree).
- The KB does **not** duplicate oracle text — entries reference cards by
  `oracle_id`; full oracle data lives in `priv_data/scryfall-oracle.json`
  (DR-1) and is joined by tools that need it (QA, classifier).

## 2. Ontology (`ontology.json`)

Versioned artifact (`version`, semver). Generated by
`scripts/gen_combo_kb_ontology.py` (regex kept as readable Python raw strings).
Bump the version and append to its `changelog` whenever a feature, resource,
event, or guard changes (RSK-3 ontology drift; QE-3 gap review each set
release).

| Block | Meaning | PRD |
|---|---|---|
| `resources` | Typed game-state quantities; `finite_zone` flags library/graveyard/exile | 6.1 |
| `events` | First-class typed occurrences trigger rules key on | 6.2 |
| `guards` | Non-consumable preconditions (zone, timing, control, summoning-sickness) with detection patterns | 6.3 |
| `features` | provides/wants/ambient vocabulary with regex patterns, scalar magnitude extractors, and `pairs_with` edges | 6.4, KB-1/2/3 |

v1 covers every KB-3 mandated trigger economy: ETB, dies, LTB, cast, sacrifice
(outlet and fodder **separately**), blink/flicker, untap, tap-ability, token
creation, mill, drain/lifegain, cost reduction, trigger doubling, recursion —
plus the combo backbone (mana add/sink, draw, damage, counters/proliferate,
extra turns, anthem). Features are seeded from the 15-role taxonomy
(`docs/role-taxonomy.md`, cross-referenced via `role_hint`).

## 3. KB entry (`entries/{shard}.json`)

Each entry is one card:

```jsonc
{
  "oracle_id": "...",          // join key to the Scryfall mirror
  "name": "Ashnod's Altar",
  "type_line": "Artifact",
  "mana_cost": "{3}", "cmc": 3.0,
  "color_identity": [],
  "is_dfc": false,

  // provides/wants/ambient: typed feature items with scalar magnitude (KB-2)
  "provides": [
    {"feature": "mana_add", "economy": "mana", "magnitude": 2,
     "provenance": "deterministic", "evidence": "Add {C}{C"},
    {"feature": "sac_outlet", "economy": "sacrifice", "magnitude": 1,
     "provenance": "deterministic", "evidence": "Sacrifice a creature:"}
  ],
  "wants": [ ... ],
  "ambient": [ ... ],          // continuous modifiers (cost reducers, doublers, anthems)

  "events_emitted": ["sacrifice"],           // PRD 6.2
  "triggers": [                               // raw When/Whenever/At clauses + guard flag
    {"trigger": "when this creature enters", "guarded": false, "provenance": "deterministic"}
  ],
  "costs": {                                  // structural + activated-ability costs
    "mana_cost": "{3}", "mana_value": 3.0,
    "activated": [{"cost": "Sacrifice a creature", "provenance": "deterministic"}]
  },
  "guards": [ {"guard": "control_requirement", "provenance": "deterministic"} ],

  "field_provenance": { "provides": "deterministic", "costs": "deterministic", ... },  // KB-4
  "provenance_summary": { "deterministic": 3 },
  "needs_llm": false,                          // true → awaits offline classifier
  "ontology_version": "1.0.1",
  "extractor_version": "det-1.0.1",
  "corpus_version": "2026-08-15T09:01:55.591+00:00"
}
```

DFCs (`is_dfc: true`) are extracted across **all faces** (PRD IN-5): the land
face of a modal DFC contributes `mana_add`, the spell face its triggers. Entries
are keyed by full Scryfall name; coverage matching aliases every face so a
decklist naming either face resolves (see §6).

## 4. Provenance encoding (KB-4) and the Tier-B gate

Every provenance-bearing item records **which extraction path produced it**, so
any downstream claim audits back to its inputs. Vocabulary
(`scripts/combo_kb_lib.py`):

| Provenance | Source | Tier-B eligible? |
|---|---|---|
| `deterministic` | Mechanical regex over oracle/type/cost | **Yes** |
| `human-reviewed` | Human sign-off (KB-7 elevated review) | **Yes** |
| `llm` | Offline per-card classifier (KB-5) | No — caps finding at Tier C until reviewed |
| `community-tag` | Scryfall Tagger stream (DR-2) | No — community-maintained, incomplete |

**The gate (build-plan decision 6b, board default = ENFORCED):** a Tier-B
verdict (Phase 3) may consume **only** `deterministic` or `human-reviewed`
items. `combo_kb_lib.tier_b_view(entry)` returns the filtered, Tier-B-legal view
of an entry plus a `tier_b_capped` list naming every field that had an
llm/community-tag item dropped — a finding relying on a dropped item must be
presented at Tier C, never Tier B. This is conservative by construction: it can
only withhold a "verified" label, never inflate one (QE-4 worst-failure-class
ordering; EI-4 tier inflation is release-blocking). The rule is unit-tested in
`tests/test_combo_kb.py`.

## 5. Build pipeline & version stamps

| Step | Script | Output |
|---|---|---|
| 1. Author ontology | `gen_combo_kb_ontology.py` | `ontology.json` (v1.0.1) |
| 2. Deterministic extraction | `build_combo_kb.py` | `entries/*.json`, `meta.json` |
| 3. Offline LLM enrichment (`needs_llm`) | `classify_combo_kb.py --emit-batch [--names-file wave.txt]` / `--apply` | enriched entries + `ontology-gaps.json` + refreshed `meta.json` |
| 4. Sampling QA | `kb_sampling_qa.py` | pass rates + human-review worksheet |
| 5. Coverage gate | `check_kb_coverage.py` | stage-1 / stage-full pass/fail |

**Stage-2 wave enrichment (`--names-file`).** Full-coverage LLM enrichment runs
in reviewable waves: `--names-file` restricts `--emit-batch` to a targeted set
(card names — front-face or full DFC name — or oracle_ids; `#` comments and
blanks ignored), fleet-first then by Spellbook variant-membership rank. `--apply`
merges responses, then:
- clears `needs_llm` for **every processed card** — an empty (no-feature) result
  is a valid "no combo-economy features" verdict (pure removal/counter/ramp), so
  waves converge toward `needs_llm` = 0. `classifier_version` is the audit stamp.
- refreshes `meta.json` dynamic counts (`needs_llm_count`,
  `deterministic_signal_count`, `llm_classified_count`, provenance/feature
  histograms) so meta never lies about coverage after enrichment.
- merges (de-duplicated) into `ontology-gaps.json` so prior waves' gaps persist.

llm-provenance items remain **not Tier-B eligible** until human-reviewed
(§Provenance); their `evidence` is model rationale, not a verbatim oracle
snippet, so the auto-QA grounding check (which requires verbatim snippets) scopes
to deterministic items only.

Three version stamps travel on every entry and in `meta.json`:
`ontology_version` (semantic model), `extractor_version` (deterministic pass),
and `corpus_version` (Scryfall mirror timestamp, DR-1/DR-7). Tier-B verdicts in
Phase 3 record the entry versions they consumed (DB-6 provenance chain: verdict
→ entry → extraction path).

## 6. Coverage (`check_kb_coverage.py`) — the two-stage Phase-1 gate

"Covered" = a KB entry exists for the card (existence, not LLM completeness).

- **Stage 1 (Phase-2 entry gate, deterministic):** every fleet-decklist card +
  the top-2,000 cards by Spellbook variant-membership count (computed from
  `data/spellbook/matcher-index.json`).
- **Stage full (Phase-4 entry gate):** every Commander-legal card in the mirror
  (31,830).

The check aliases every DFC face, so a decklist line naming either face (e.g.
"The Invincible Iron Man" for `Tony Stark // The Invincible Iron Man`) resolves.

## 7. Extending per set release (QE-3 / RSK-3)

1. Refresh the mirror (`refresh_scryfall_mirror.py`) → new `corpus_version`.
2. Gap review: run the classifier over new cards; anything unmodelled lands in
   `ontology-gaps.json`. Extend `ontology.json` (bump version + changelog) to
   cover new mechanics; log residual blind spots as user-visible at the
   corpus-version level.
3. Rebuild deterministic entries, re-run sampling QA, re-run the coverage gate.
4. Re-calibrate ranking when the ontology version changes (QE-6, Phase 3).
