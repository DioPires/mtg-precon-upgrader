## Method
- **Selection:** deterministic, reproducible order — oracle_id ascending over the still-`needs_llm`
  set (the local mirror carries no `edhrec_rank`; oracle_id is the stable, auditable signal).
  Wave 7 = first 300 (`Armory Veteran` .. `Battle-Mad Ronin`), Wave 8 = next 300
  (`Everything Comes to Dust` .. `Coronation of Chaos`), Wave 9 = next 300
  (`Songbird, Sonic Screamer` .. `Untamed Hunger`), Wave 10 = next 300
  (`The Mimeoplasm` .. `Soul Shatter`).
- **Classifier:** offline build-time batch (KB-5 / NF-1 — never on the query path). Prompts
  emitted via `classify_combo_kb.py --emit-batch` (IN-7-hardened: card oracle text fenced as
  untrusted data; the system instruction forbids treating fenced text as directives),
  classified against the closed v1.0.1 ontology (30 features), then `--apply` per wave.
- **Provenance:** every output stamped `llm` → Tier-C capped, **never** Tier-B-eligible until
  human review (`TIER_B_PROVENANCES = {deterministic, human-reviewed}`; `'llm'` ∉ that set,
  verified directly).
- **High empty rate is correct by design.** 1,041 / 1,200 cards classify empty because a
  long-tail, non-combo card's mechanics usually fall outside the v1.0.1 combo-economy ontology.
  Such cards are logged as QE-3 ontology gaps rather than force-fit to an ill-fitting feature —
  empty ≠ missed; empty = "no ontology-expressible combo signal."

## Per-wave machine validation (independent of the apply harness)
Every wave's merged responses were re-validated against the exact card oracle text each
classifier was shown, before `--apply`:
- **300/300 oracle_id match** per wave (every response maps to a card in that wave's target
  set; 0 missing, 0 extra, 0 duplicate).
- **0 OOV** feature ids (every id ∈ the v1.0.1 30-feature ontology).
- **0 kind-mismatch** (every feature sits in the array matching its ontology `kind`:
  `provides` / `wants` / `ambient`). A mechanical normalization pass caught **1** item emitted
  as `graveyard_payoff` under `provides` (it is a `wants` feature) and reassigned it to the
  ontology-defined array before apply — no feature id or evidence was changed.
- **0 non-verbatim evidence** — every non-empty `evidence` string is an exact substring of that
  card's fenced oracle text, ≤ 80 chars. The same normalization truncated **1** evidence string
  of 89 chars to its verbatim 80-char prefix. 0 items were dropped.
- **Magnitudes** all integer ≥ 1.
