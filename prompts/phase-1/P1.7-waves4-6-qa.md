## Method
- **Selection:** Spellbook variant-membership no longer applies (all participating cards were
  cleared in Wave 3). The long tail is drained in a **deterministic, reproducible order**:
  oracle_id ascending over the still-`needs_llm` set (the local mirror carries no
  `edhrec_rank`, so oracle_id sort is the stable, auditable signal). Wave 4 = first 300,
  Wave 5 = next 300 (`0ee28549..1be478ee`), Wave 6 = next 300 (`1c19b04d..2b43c7de`).
- **Classifier:** offline build-time batch (KB-5 / NF-1 — never on the query path). Prompts
  emitted via `classify_combo_kb.py --emit-batch --names-file` (IN-7-hardened: fenced,
  untrusted oracle data; the system instruction forbids treating fenced text as directives),
  classified against the closed v1.0.1 ontology, then `--apply`.
- **Provenance:** every output stamped `llm` → Tier-C capped, **never** Tier-B-eligible until
  human review (`TIER_B_PROVENANCES = {deterministic, human-reviewed}`).
- **High empty rate is correct by design.** 732 / 900 cards classify empty because a long-tail,
  non-combo card's mechanics usually fall outside the v1.0.1 combo-economy ontology. The
  classifier is instructed to log such cards as QE-3 ontology gaps rather than force an
  ill-fitting feature — so empty ≠ missed, empty = "no ontology-expressible combo signal."
