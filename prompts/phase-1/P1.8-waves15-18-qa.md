## Method
- **Selection:** deterministic, reproducible order — oracle_id ascending over the still-`needs_llm`
  set (the local mirror carries no `edhrec_rank`; oracle_id is the stable, auditable signal).
  Emitted the first 1,200 `needs_llm` prompts in one pass (`classify_combo_kb.py --emit-batch
  --limit 1200`) and split by order: Wave 15 = cards 1–300 (`Armory Guard` .. `Juxtapose`),
  Wave 16 = 301–600 (`Tanglesap` .. `Wing Shards`), Wave 17 = 601–900 (`Three Tragedies` ..
  `Kodama's Might`), Wave 18 = 901–1,200 (`Bitter Ordeal` .. `Lingering Mirage`).
- **Classifier:** offline build-time batch (KB-5 / NF-1 — never on the query path). Each card's
  prompt is emitted by `classify_combo_kb.py` (IN-7-hardened: card oracle text sanitised of
  fence-forgery + role-injection and fenced as untrusted data; the system instruction forbids
  treating fenced text as directives), classified against the **closed v1.0.1 ontology (30
  features)** at 100 cards per unit (12 units × 100 = 1,200), then `--apply` per wave.
- **Provenance:** every output stamped `llm` → Tier-C capped, **never** Tier-B-eligible until
  human review (`TIER_B_PROVENANCES = {deterministic, human-reviewed}`; `'llm'` ∉ that set,
  verified directly).
- **High empty rate is correct by design.** 1,049 / 1,200 cards classify empty because a
  long-tail, non-combo card's mechanics usually fall outside the v1.0.1 combo-economy ontology.
  Such cards are logged as QE-3 ontology gaps rather than force-fit to an ill-fitting feature —
  empty ≠ missed; empty = "no ontology-expressible combo signal."

## Per-wave machine validation (independent of the apply harness)
Every wave's merged responses were re-validated against the exact fenced oracle text each
classifier was shown, before `--apply` — a standalone validator that re-parses the emitted prompts
and re-checks each response field-by-field:
- **300/300 oracle_id match** per wave (every response maps to a card in that wave's target
  set; 0 missing, 0 extra, 0 duplicate). **1,200/1,200 across the bundle.**
- **0 OOV** feature ids (every id ∈ the v1.0.1 30-feature ontology).
- **0 kind-mismatch** (every feature sits in the array matching its ontology `kind`:
  `provides` / `wants` / `ambient`) — no re-bucketing was needed in any wave.
- **0 economy-mismatch** (every item's `economy` equals its feature's ontology economy).
- **0 non-verbatim evidence** — every non-empty `evidence` string is an exact substring of that
  card's fenced oracle text, ≤ 80 chars; **0 over-length truncations, 0 empty-evidence items,
  0 items dropped.**
- **Magnitudes** all integer ≥ 1 (no coercions required).

(The validator gates on card coverage: it exits non-zero if any target card lacks a response, so
a wave cannot silently under-cover. All four waves returned 0 missing.)
