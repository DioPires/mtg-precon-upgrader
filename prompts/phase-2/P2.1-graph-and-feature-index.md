# P2.1 — Provides/wants graph + feature-index

**Requirements:** DC-1, DC-3, DC-6, TX-1, TX-2

## Objective
Build the deck-scoped provides/wants graph from the merged combo-KB
(`data/combo-kb/`), and a compact per-card feature-index that paste mode can load
in the browser.

## Deliverables
- `scripts/combo_synergy_lib.py` — engine (single source of truth). Loads KB
  entries, resolves a decklist to KB entries by oracle identity (DFC face
  aliasing), builds the provides/wants graph using the ontology `pairs_with`
  compatibility relation.
- `scripts/build_synergy_index.py` — emits `data/combo-kb/feature-index.json`
  (compact: oracle_id → name/ci/provides/wants/ambient with scalar magnitudes)
  and `feature-index.meta.json`.

## Acceptance
- Tier-C view MAY consume `llm` provenance items (Tier-C only; Tier-B gate is
  Phase 3). Deterministic + llm feature items both feed the graph.
- Every reported edge is explainable: which feature of X satisfies which need of
  Y, with magnitudes (DC-3). No edgeless "good together" output.
- DC-6 designed-for-limitation: the ontology is a lossy compression; the graph
  never claims completeness.
- Committed JSON is plain, `sort_keys=True`, stable order; feature-index ≪ 150 MB
  working-tree gate (~3 MB).
