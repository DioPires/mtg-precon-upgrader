# P4.3 — Deck-URL input (IN-2 / IN-4)

**Requirements:** IN-2 (accept Moxfield + Archidekt deck URLs, resolve to decklists), IN-4 (commander
propagation).

`web/src/lib/deckUrl.ts` — `parseDeckUrl` recognizes Moxfield / Archidekt deck URLs; `mapMoxfield` /
`mapArchidekt` are pure, unit-tested response mappers (v3 + legacy v2 board shapes; Archidekt commander
category → commander propagation, maybeboard/sideboard skipped); `resolveDeckUrl` does the thin fetch
and throws a typed `DeckUrlError` with an actionable message on failure.

**Architectural constraint (flagged to CEO):** The Grimoire is static/backendless (locked, DEC-149), so
resolution is a direct client-side fetch of the host's public API. Both hosts currently gate cross-origin
browser access (Archidekt pins its CORS origin to localhost:3000; Moxfield 403s non-browser agents), so a
direct fetch is typically CORS-blocked in production. The resolver therefore degrades to an actionable
"export the list and paste it below" message rather than failing opaquely. A runtime CORS proxy would lift
the wall but adds a third-party query-path dependency + terms exposure (RSK-4) — surfaced to the board as a
decision, not adopted unilaterally.
